# Sales Order — Mobile App

A standalone, TallyPrime-style mobile app for **placing sales orders directly from a phone**.
Everything is stored **on the device** — no server, no login, works fully offline.

![tabs: Orders · New · Items · Parties](www/icon.svg)

## Features

- **Create sales orders** — pick a party, add items with quantity & rate, automatic **GST** and totals.
- **Item catalog** — searchable stock items with unit, rate, GST %, HSN.
- **Party (customer) catalog** — name, phone, place, GSTIN, address.
- **Order history & status** — filter by Pending / Confirmed / Delivered / Cancelled; edit or delete.
- **Share / Print / PDF** — share an order to WhatsApp/email, or print to PDF.
- Ships with demo items & parties so you can create an order immediately.

The app comes preloaded with 8 sample items and 4 sample parties. Add your own from the **Items** and **Parties** tabs; delete the samples anytime.

## Try it right now (no build needed)

The `www/` folder is a complete web app.

**On your PC:**
```bash
npm run serve
```
Then open the printed `http://localhost:8791/` in a browser.

**On your phone (same Wi-Fi):** open `http://<your-pc-ip>:8791/` and use
**Browser menu → “Add to Home screen”** — it installs like an app and runs offline.

## Export a Sales Order to TallyPrime (XML import)

Every saved order has a **⬇ Download Tally XML (Sales Order)** button (order detail
screen). It produces a TallyPrime-importable voucher file.

1. In the app, open **Sales Orders → ⚙ Tally** (top-right) and set the names to
   match your Tally: **Sales ledger**, **Sales Order voucher type**, optional
   **Company** and **Godown**. Save.
2. Open an order → **Download Tally XML** → you get `SO-0001.xml`.
3. In TallyPrime: **Gateway of Tally → Import → Vouchers** (or Import Data →
   Vouchers) → select the `.xml` file → Import. It creates a **Sales Order** voucher.

> The party ledger and stock items named in the order must already exist in Tally
> (or be created there). Names must match exactly. The first import is a quick test —
> if Tally reports a mismatch, adjust the names in **⚙ Tally** settings and re-export.

## Build the installable Android APK

This project uses [Capacitor](https://capacitorjs.com) to wrap the app into a real `.apk`.
Pick **one** of the two paths below.

### Option A — Cloud build (easiest, no Android tools on your PC)

This machine has no Android SDK, so building here isn’t possible — build it on GitHub instead:

1. Create a free GitHub account and a new **empty repository**.
2. Push this `MobileSalesOrder` folder to it:
   ```bash
   cd MobileSalesOrder
   git init && git add . && git commit -m "Sales Order app"
   git branch -M main
   git remote add origin https://github.com/<you>/<repo>.git
   git push -u origin main
   ```
3. GitHub automatically runs `.github/workflows/build-apk.yml`.
   Open the repo → **Actions** tab → the latest run → **Artifacts** →
   download **`sales-order-apk`**. Inside is **`app-debug.apk`**.
4. Copy that APK to your phone and tap it to install
   (enable *Install unknown apps* for your file manager when prompted).

### Option B — Local build (needs Android Studio)

Requirements: **Node.js 18+**, **JDK 17** (this PC currently has JDK 11 — install 17),
and **Android Studio** (includes the Android SDK).

```bash
cd MobileSalesOrder
npm install
npx cap add android          # creates the android/ project (first time only)
npx cap sync android
npx cap open android         # opens Android Studio
```
In Android Studio: **Build → Build Bundle(s)/APK(s) → Build APK(s)**.
The APK lands in `android/app/build/outputs/apk/debug/app-debug.apk`.

> After editing anything in `www/`, run `npx cap sync android` to copy changes into the APK project.

## Customising

| What | Where |
|------|-------|
| App name / package id | `capacitor.config.json` (`appName`, `appId`) |
| Demo items & parties | `www/js/store.js` (the `SEED` object) |
| Colours / theme | `www/css/styles.css` (`:root` variables) |
| Screens & logic | `www/js/app.js` |
| App icon | `www/icon.svg` (Android launcher icons are generated by Android Studio) |

## Project layout

## Notes & roadmap

- Data lives in the browser/WebView storage of the device. To move data between phones,
  a future version can add JSON export/import or a cloud sync (Firebase).
- You chose a **standalone** app. If you later want orders to flow into your real
  TallyPrime company, that’s an add-on: the app would POST a Tally XML voucher to the
  Tally Gateway on your PC (`http://<tally-pc>:9000`). Ask and I’ll wire it up.
